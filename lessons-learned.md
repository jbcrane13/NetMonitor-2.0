# Lessons learned — NetMonitor-2.0

Project-specific notes for agents. Global lessons live in `~/.claude/lessons-learned.md`; testing-specific history is in `docs/TESTING-LESSONS-LEARNED.md`.

## 2026-09-18 — Architecture-deepening epic #273 (S1–S7)

- **Run the macOS unit target on `blakes-mac-mini-2` with per-test timeouts.** `xcodebuild test … -only-testing:NetMonitor-macOSTests` without `-test-timeouts-enabled YES -default-test-execution-time-allowance 90 -maximum-test-execution-time-allowance 120` hangs indefinitely in the live-Bonjour suites (test host idle for 30+ minutes). With the flags, ten tests fail by time limit or assertion on `main` regardless of the change under test — see #287 for the list. Compare a branch's failure list against `main`'s before treating any of them as a regression. **Update (#299, 2026-09-20):** the nine live-Bonjour tests in #287's list are gated behind `NETMONITOR_LIVE_TESTS` now (see the entry below) and no longer need the timeout flags to avoid hanging a merge; the tenth, `PortScannerInvalidPortTests` "port 0 is rejected", was a real bug fixed in #305 and now passes normally.
- **The node has no xcodegen or Homebrew on its non-interactive PATH.** It builds from the committed `NetMonitor-2.0.xcodeproj/project.pbxproj`, so any change that adds a file to an app or test target must run `xcodegen generate` locally and commit the regenerated pbxproj.
- **The node's LAN interface is en1, not en0.** `NetworkUtilities.detectLocalIPAddress/detectLocalIPv4Network/detectDefaultGateway` default to `"en0"`; code that scans "the local network" without an active `NetworkProfile` must probe interfaces (the coordinator now does, `DeviceDiscoveryCoordinator.selectFallbackInterface`). A live-scan gate on the node that assumes en0 reports zero devices.
- **Live-scan gate for discovery changes:** `TEST_RUNNER_NETMONITOR_LIVE_SCAN=1 xcodebuild test … -only-testing:NetMonitor-macOSTests/DeviceDiscoveryCoordinatorLiveScanTests` prints `LIVE_SCAN devices=<n> gateway=<found|missing>`; baseline recorded 2026-09-18 on the pre-S6 coordinator was `devices=0 gateway=missing`, post-S6 `devices=1 gateway=found`.
- **Known environmental package-test failures** (do not "fix" in unrelated PRs): NetworkScanKit `ScanPipelineRealIntegrationTests` "finds at least 1 device" needs a live LAN; NetMonitorCore `SSLCertificateContractTests` "days between two known dates" adds 60×86400 s to `now` and crosses a DST change for part of each year.
- **CI SwiftLint/SwiftFormat/coverage jobs fail on `main` already (#264)**; they are not merge blockers for otherwise-green PRs, but lint your changed files locally with `--baseline .swiftlint_baseline.json`.
- **The sandboxed macOS app CAN open the ICMP socket `ICMPLatencyPhase` uses** — corrected 2026-09-19. The phase opens an unprivileged `SOCK_DGRAM` ICMP socket, which needs no entitlement; only the raw `ICMPSocket` does. Measured inside the app process on mini-pro-2: `socket(AF_INET, SOCK_DGRAM, IPPROTO_ICMP)` → fd 6, errno 0, gateway 3.96 ms. docs/ADR-macOS.md ADR-003 makes real ICMP primary and `ProcessPingService` (shell `/sbin/ping`) the fallback, so the engine's phase honours the ADR. The earlier claim here — that shell ping was the macOS latency source of record because ICMP could not work — was wrong and propagated from D14 of the 2026-09-18 plan.
- **Coordinator tests inherit the host's real network profile.** `NetworkProfileManager()` with default arguments reads `UserDefaults.standard` and calls `detectActiveProfiles` (`NetworkProfileManager.swift:14-25`), so on a real machine `effectiveProfileID()` returns a live profile UUID. Any test that seeds a `LocalDevice` with the default `networkProfileID == nil` then finds it invisible to `fetchDevices(for:)`, `loadPersistedDevices` and `markOfflineDevices` — passing on a machine with no detectable profile and failing on one that has it. Inject `NetworkProfileManager(userDefaults: UserDefaults(suiteName: UUID().uuidString)!, activeProfilesProvider: { [] })` for determinism. Found 2026-09-19 when #297's E1 test passed locally and failed on mini-pro-2; several pre-existing coordinator tests still carry this hazard.
- **A phase that is only ever stubbed to return nil is not tested.** #297 added four macOS `ScanPhase`s whose whole purpose is writing enrichment back to SwiftData, and the suite exercised them only with dependencies returning `nil`/`false` while the golden-row test opted out of enrichment entirely — so a phase that silently wrote nothing would have passed everything. When a type's job is a side effect, assert the side effect with non-nil inputs.
- **Known environmental package-test failure, third one — now gated, not expected-failing (#299, 2026-09-20):** NetMonitorCore `TracerouteServiceIntegrationTests` "trace stream finishes (does not hang) within reasonable time for loopback" takes ~30 s against a 15 s expectation and its suite alone runs ~8 minutes; it fails under plain `swift test`, not only on the node. The whole suite is now behind `@Suite(.enabled(if: LiveTestGate.isEnabled))`, gated on `NETMONITOR_LIVE_TESTS` (see below), so a default `swift test` run reports it skipped rather than failed.
- **Never trust a bare "N tests passed" from `xcodebuild test`.** When a test crashes the runner, xcodebuild restarts it and prints `Restarting after unexpected exit, crash, or test timeout; summary will include totals from previous launches` — then the final summary still reads `✔ Test run with N tests ... passed` while the process exits 65 and **no `✘` line names the crashing test**. This hid a `PortScannerService` trap for days (#305): the macOS target reported 309 tests in 50 suites, and fixing the crash raised it to **431 in 70** — the crash had been swallowing 122 tests and 20 suites. It then hid six more crashing suites (#309). Every script that runs an app target must grep for `Restarting after unexpected exit` **and** `Fatal error` and treat either as failure, not just `✘` and the summary line. A filter that greps only for pass/fail markers will report a crashing suite as green.
- **Force-unwrapping a converted integer is a crash, not a lint nit.** `NWEndpoint.Port(rawValue: UInt16(port))!` looks defensive because of the `!` on a failable init, but the trap is `UInt16(_: Int)`, which *aborts the process* above 65535 rather than returning nil. Use `UInt16(exactly:)` and handle the nil. Validate at the public entry point as well, so callers can't reach the conversion with garbage (#305).
- **The crash *reason* never reaches xcodebuild's output — read the `.ips` report.** Every runner crash in #309 printed nothing to stdout/stderr (no `Fatal error`, no exception text). The cause was only in `~/Library/Logs/DiagnosticReports/NetMonitor-*.ips` on the node: `exception.type`, `lastExceptionBacktrace` (ObjC exceptions), and the faulting thread's frames. Parse them with python (`json.loads` of everything after the first line); with ssh single-quoting, keep the python free of single quotes.
- **A discarded `ModelContainer` is a use-after-free, and it traps silently.** `let (_, context) = try makeStore()` frees the container at the end of the statement; `mainContext` does not retain it, and the next SwiftData call is `EXC_BREAKPOINT` with SwiftData frames and no message. Six tests did this. Hold it with `defer { withExtendedLifetime(container) {} }` — the repo's older `_ = container` idiom only works because Debug builds don't shorten local lifetimes. A crash like this is attributed to whatever test is *running*, which may not be the test that caused it.
- **A test that starts a real scan and returns has not finished.** `NetworkDetailViewScanRegressionTests` started nine production-pipeline scans and stopped two; the LAN scan kept running for a minute after the test's container died and trapped during an unrelated PortScanner suite (`[ICMPLatency] ICMP ping sweep complete` in the log was the tell). Unit tests must inject a fixture `pipelineFactory` (holding phase or `ScanPipeline(steps: [])`) and `defer { coordinator.stopScan() }`; `handleScanProgress` now refuses to touch SwiftData after cancellation so `stopScan()` is sufficient.
- **`BGTaskScheduler.submit` raises, it does not throw.** For an identifier with no registered launch handler it raises `NSInternalInconsistencyException` (`_handleSubmissionWithoutRegistrationForTaskRequest:`), which Swift `try`/`catch` cannot intercept — the `do`/`catch` around every submit site never protected anything, and the test named "does not crash when called outside app context" was the crasher. `BackgroundTaskService` now takes `submitTask`/`cancelTask` seams and refuses to submit before `registerTasks()`.
- **The iOS target was also crash-truncated.** It reported 267 tests / 42 suites for as long as anyone looked; with the BG and Settings crashes fixed it reports **913 / 128**. Any historical "iOS green" claim covered under a third of the suite. With #312 on `main` the true sizes are **macOS 968 / 148** and **iOS 913 / 128** (macOS went 309/50 → 431/70 → 968/148 as three successive crashes were removed). `~/rel-verify.sh` on mini-pro-2 enforces those as floors and fails on any `Restarting after unexpected exit` or `Fatal error` line.
- **Two node-scripting traps that each cost half an hour:** (1) `xcodebuild -destination 'platform=iOS Simulator,name=iPhone 17'` fails with "Unable to find a device" after `simctl shutdown all` — boot by UDID (`D95ED668-046D-4983-92D4-1449725C9EF6`) and wait with `simctl bootstatus <udid> -b`; (2) under `set -u`, zsh rejects `local a=$1 log=~/x-$a.log` in one statement (`a: parameter not set`) — assign on separate lines.
- **Worker orchestration that worked:** Sonnet subagents with `isolation: worktree`, branches cut from `origin/main` (not the orchestrator's local `main`), ownership acknowledgement comment before editing, checkpoint comments every ~10 minutes, orchestrator reviews each PR (Standards + Spec) and runs the node tests serially before merging. Frontier sizes of 4 → 2 → 1 kept file ownership disjoint.

## 2026-09-20 — #299: gate live-network tests, fix the IDW performance assertion

- **Two env flags, two meanings — do not conflate them.** `NETMONITOR_LIVE_SCAN=1` (existing, unchanged) means "run the live discovery scan" and only gates `DeviceDiscoveryCoordinatorLiveScanTests`. `NETMONITOR_LIVE_TESTS=1` (new) means "run tests that need a real LAN, live Bonjour peers, or simulator App Intents" and gates suites via `@Suite(.enabled(if:))`: macOS `BonjourDiscoveryStreamTests`, `BonjourDiscoveryObservableTests`, `BonjourDiscoveryCancellationTests`, `BonjourServiceDeduplicationTests`, `BonjourServiceSendabilityTests`, `BonjourServiceTypeFilteringTests` (`Tests/NetMonitor-macOSTests/BonjourDiscoveryServiceTests.swift`); iOS `SaveWiFiReadingIntentTests`; NetMonitorCore `TracerouteServiceIntegrationTests`. Both flags read as `ProcessInfo.processInfo.environment["<NAME>"] == "1"`; via `xcodebuild test` only `TEST_RUNNER_`-prefixed variables reach the test process, so the node invocation is `TEST_RUNNER_NETMONITOR_LIVE_TESTS=1`. The predicate lives once per test target in a `LiveTestGate` helper (`Tests/NetMonitor-macOSTests/Helpers/LiveTestGate.swift`, `Tests/NetMonitor-iOSTests/Helpers/LiveTestGate.swift`, `Packages/NetMonitorCore/Tests/NetMonitorCoreTests/Helpers/LiveTestGate.swift`) rather than repeating the string literal — one copy per target because each compiles independently (app targets + an SPM package), not one file shared across all three.
- **Prefer suite-level `.enabled(if:)` over early-return-inside-test for gating.** An early return with `#expect(Bool(true))` (the pre-existing pattern in `DeviceDiscoveryCoordinatorLiveScanTests`) reports the test as *passed*, which hides that it never actually ran. `@Suite(.enabled(if: LiveTestGate.isEnabled))` reports the whole suite and its tests as *skipped* — verified locally: `swift test --filter Traceroute` prints `➜ Suite TracerouteServiceIntegrationTests skipped.` plus one skip line per test when the flag is unset, and runs for real when `NETMONITOR_LIVE_TESTS=1` is exported.
- **A wall-clock performance bound must survive machine load, not just machine speed.** `PostScanRefinementTests` "IDW refinement under 5 seconds for 2000 points" measured 57 s on the automation node under load — not a flaky bound, a load-dependent one, and gating it away would hide a real algorithmic regression (e.g. IDW accidentally going quadratic). Replaced the absolute 5 s bound with a relative one: 2000 points must take no more than 8x as long as 500 points. `HeatmapRendererTests`-style local measurement (release build, 3 runs) confirmed `HeatmapRenderer.render` is linear in point count (fixed-size grid, O(points) IDW inner loop per pixel, no superlinear preprocessing) — the real ratio came out to ~4.0x consistently, so 8x gives 2x headroom for a load skew between the two renders while staying well below the ~16x a quadratic regression would produce. Floor the small-N timing (>0.02s) to avoid measurement-quantization noise on fast machines.
- **`#expect(_:_:)`'s comment argument does not accept a runtime-concatenated `String` via `+`.** `#expect(cond, "a" + "b(\(x))")` fails to compile with "cannot convert value of type 'String' to expected argument type 'Comment?'" — use a single string-interpolation literal instead of concatenating two literals with `+`.
- **This gateway host runs concurrent worker sessions that contend for build resources.** Multiple `xcodebuild build-for-testing` and `swift test` invocations from sibling workers (e.g. `w294-core`) running at the same time can produce spurious `error: the following command failed with exit code 0 but produced no further output` on unrelated files with `xcodebuild`'s overall exit code still 0 — a resource-contention artifact, not a real compile error. Confirmed by rerunning the identical command alone: zero errors. Re-run once, quiescently, before treating such errors as real.
- Known environmental package-test failures **not** touched by #299 (still expected-failing, out of scope): NetworkScanKit `ScanPipelineRealIntegrationTests` "finds at least 1 device" (needs a live LAN) and NetMonitorCore `SSLCertificateContractTests` "days between two known dates" (DST). Do not gate these in unrelated PRs without explicit scope for it.

## 2026-09-22 — #313/#315: the iOS smoke suite on iOS 26, and the bug it found

- **iOS 26 rewrites the XCUI accessibility tree; dump it before guessing.** Three facts measured on the iOS 26.5 simulator (throwaway `SmokeDiagTests`, `~/smoke-diag.txt` on the node): (1) a settings `Toggle` row is exposed as one full-width `Switch`, so `tap()` at its centre hits the label and changes nothing — use `tapTrailingEdge`; (2) an outer container's `.accessibilityIdentifier` is stamped over its descendants' identifiers (`screen_networkTimeline` replaces `timeline_list_events`, `pingTool_card_statistics` hides every `toolStats_item_*`), and controls are not exempt: the Ping screen's TextField kept `pingTool_input_host`, but every control on the Geo Trace screen was stamped `screen_geoTrace` — where a control sits relative to the container that carries the screen id decides it, so address controls by type, placeholder and label when in doubt; (3) a `NavigationLink` card gets a synthesised button identifier made of its children's (`tools_card_ping-tools_card_ping-…`), and the plain identifier lands on non-hittable images and texts — match buttons with `identifier BEGINSWITH`. Assert on what the screen renders (labels, the Clear button that only exists with events), not on nested container ids.
- **Run the diagnostic once, then read frames, not verdicts.** Two blind repair cycles (swipe vs. drag, tab-bar rule) cost ~25 minutes each; a 40-second test that logs each card's frame after every gesture settled the scroll question in one run and exposed the app bug below.
- **`.scrollTargetBehavior(.viewAligned)` over a child taller than the viewport makes the middle unreachable.** `ToolsView` snapped to its outer VStack's three children; the grid child is ~1200pt, so the Tools screen only rested at three offsets and Speed Test / World Ping could never be tapped on an iPhone (#315, shipped in 2.2.0 since 1b5f85d). Keep view-aligned snapping for rows of small chips (SubnetCalculator examples, heatmap visualisation picker); never put it over a section that can exceed the screen.
- **The node has no `xcodegen`.** To run an uncommitted test file there, regenerate `project.pbxproj` on the gateway with the file in place and scp both; `git checkout -- NetMonitor-2.0.xcodeproj` afterwards on both machines.
- **`grep -c` returning 0 exits 1 and short-circuits `&&` chains.** A heredoc chained after `ssh … grep -c` silently never ran and the node re-ran the previous diagnostic; check `wc -l` or drop the `&&` when a count of zero is a valid outcome.
- **The permission classifier blocks release merges and release scripts in auto mode.** `gh pr merge` and the GitHub MCP merge were denied ("Merge Without Review"); `release-bump.sh` was denied as a production deploy but the same edits by hand were allowed. Plan for the human to merge release PRs; keep archives/exports (no upload) runnable.
