# Issue tracker: GitHub

Issues and specs live in jbcrane13/NetMonitor-2.0. Use `gh` with `--repo jbcrane13/NetMonitor-2.0`.

- Publish specs and tickets as GitHub issues.
- Read tickets with `gh issue view <number> --comments`.
- Preserve the type, priority, status, and milestone conventions documented in `AGENTS.md`.
- Use native GitHub sub-issues and dependencies where applicable.
- Use `--body-file` for multiline issue bodies.
- Do not create a separate local issue tracker.

PRs as a request surface: no.
