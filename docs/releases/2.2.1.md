# NetMonitor 2.2.1 — release notes (draft)

Both App Store products are live at **2.2.0** (23 April 2026). 2.2.1 was configured in the repository and reached a release candidate in August (#262) but never shipped; this release carries that work plus everything merged since. Build numbers follow ADR-011 (query App Store Connect for the latest before archiving).

## App Store "What's New" (user-facing)

### NetMonitor (iOS)
- Scans now stop the moment you ask, and background refresh respects system limits.
- The dashboard health score comes from the shared scoring engine, so it matches what NetMonitor Pro reports for the same network. Latency colours use one scale everywhere (green under 50 ms, amber to 150 ms).
- The Wi-Fi icon now reflects your actual signal strength.
- The Mac link recovers on its own: if the connection to your Mac goes quiet, it reconnects within about 45 seconds instead of showing "Connected" indefinitely.
- Large histories stay responsive; storage problems are shown clearly with a recovery option instead of failing silently.
- Port scanner rejects invalid port numbers instead of scanning them.

### NetMonitor Pro (macOS)
- Faster, more complete device discovery: the Mac now uses the same scan engine as iOS, adding SSDP and TCP discovery, ICMP-based latency, and in-scan name, vendor and port enrichment.
- Devices that have gone offline are no longer re-probed on every scan.
- Device list filtering and sorting is shared with iOS and covered by tests; the "Last Seen" labels are consistent between the list and detail views.
- Companion link framing is shared with iOS, with one 1 MiB frame limit on both sides.
- Scans stop when you ask; storage problems are shown with a recovery option.

## Engineering changelog (since 2.2.0)

### Reliability & responsiveness (#262, PR #265 — August)
- Once-only, launch-scoped iOS background task registration.
- Cancellation-aware scan engine, phases, connection budget, and background expiration; hard per-phase deadlines.
- Explicit SwiftData recovery state on both platforms with diagnostic export; v2.2.0 store reopen coverage.
- 10 Hz scan-progress coalescing; bounded SwiftData queries; one-fetch/one-save macOS device merge.
- 1 MiB incremental companion framing, generation-safe callbacks, capped exponential reconnect.
- Distinct scanning / offline / empty dashboard states; release-critical accessibility identifiers.

### Architecture deepening, epic #273 (PRs #281–#288 — 18 Sept)
- S1 #284: connection budget behind `withConnectionSlot`; macOS quick port scan now budgeted.
- S2 #282: macOS companion link consumes Core's frame decoder/encoder; protocol doc corrected to length-prefixed framing.
- S3 #285: PortScanner, Ping and Bonjour resolution on one `withNWConnection` primitive.
- S4 #283: macOS device list derivation (`DeviceList`) in Core. *Product-visible:* the devices panel's saved sort preference resets once.
- S5 #281: iOS dashboard reads health score and severity from Core. *Product-visible:* the score value changes; latency dot boundary 120 → 150 ms; Wi-Fi icon varies with signal.
- S6 #288: macOS discovery runs through `ScanEngine` (gains SSDP, TCP discovery, weighted progress).
- S7 #286: typed `ScanPhaseID`; dead `ScanStrategy` surface removed (ADR-021).

### Scan seam completion, epic #300 (PRs #302–#303 — 19 Sept)
- Shared bounded-concurrency helper; ranked latency precedence inside `ScanAccumulator` (ADR-014 placement); `ICMPLatencyPhase.probeCount`.
- macOS enrichment as real `ScanPhase`s: shell name resolution, vendor lookup, quick port scan, shell-ping fallback. *Product-visible:* enrichment applies only to devices seen in the current scan (E1); latency is ICMP-sourced, min of 3 (E3). `ARPScannerService` removed (#291).

### Companion, fixes and test integrity (20 Sept)
- #307: `CompanionLinkSession` — heartbeat liveness and reconnect state in one Core type. *Product-visible:* a half-open Mac link reconnects after ~45 s of silence.
- #306: `PortScannerService.scan` validates ports (port 0 was scanned; >65535 trapped).
- #308: live-network tests gated behind `NETMONITOR_LIVE_TESTS`; IDW performance bound made load-independent.
- #312: test-runner crashes fixed (#309) — six tests freed their `ModelContainer` mid-test; two suites leaked real LAN scans past their own lifetime; `BackgroundTaskService` now refuses to submit before registration instead of raising an uncatchable exception; `handleScanProgress` never touches SwiftData after cancellation. The iOS target's true size is 913 tests, not the 267 it had been reporting.

### May 2026 batches (PRs #226–#249)
- Architecture review P1/P2: concurrency and DIP cleanup, dead protocol removal, `fetchLimit` on unbounded `@Query`s, `SchemaMigrationPlan` scaffold, composition root and value-based navigation, shared `HeatmapSurveyState`.
- #245 iOS 26 Liquid Glass APIs adopted over `.ultraThinMaterial`; #246 SwiftUI 6 APIs. *(Verify visible impact before listing in App Store copy.)*
