# NetMonitor 2.2.3 — release notes (iOS/widget build 25 / macOS 1795307064; builds 24 / 1795306090 turned UniFi lookup off and were replaced)

2.2.3 is a patch on 2.2.2 (iOS 23 / macOS 1795258945, live 2026-11-21). UniFi device lookup now needs an enrolled controller:

- The user enters the controller's address and API key in Settings. NetMonitor verifies the controller before saving: standard HTTPS validation for its address, or, for a self-signed controller, a SHA-256 certificate fingerprint the user enters. No key is sent while checking.
- The key is saved bound to that controller (address and fingerprint) in one Keychain record. Every request that carries it goes through `URLSessionUniFiTransport`, shared by both apps: HTTPS to the enrolled host only, the TLS challenge cancelled unless it is that controller, redirects refused, no proxy.
- A key saved by 2.2.2 is never reused: scans skip UniFi until the user enrolls (entering the key again) or removes it. Settings shows the lookup as paused, and "Check Controller" says why an enrolled controller isn't verified.
- Ordinary discovery, and UniFi details from discovery that needs no key, are unchanged.

## App Store "What's New" (user-facing)

### NetMonitor (iOS)
- Security improvements.
- UniFi device lookup now uses a controller you enroll in Settings. A key saved in an earlier version is paused until you enroll or remove it.

### NetMonitor Pro (macOS)
- Security improvements.
- UniFi device lookup now uses a controller you enroll in Settings › Network. A key saved in an earlier version is paused until you enroll or remove it.
